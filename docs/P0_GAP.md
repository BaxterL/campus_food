# P0 缺口清单

相对底座 yshop-drink 开源能力：

## 已有（可直接用）

| 能力 | 说明 |
|------|------|
| 多门店 + 商品 SKU | 管理端录入 |
| 自取 `orderType=takein` | 下单/列表/详情 |
| 取餐号 `numberId` | 下单写入 `yshop_order_number` |
| 支付骨架 | 微信 / 余额；管理端线下付 |
| 自取完结 | 管理端「出单/发货」对自取会直接收货 |

## 本仓已补（P0）

| 缺口 | 处理 |
|------|------|
| `verify_code` 闲置 | 下单时写入核销码（取餐号 4 位） |
| 扫码/输码核销 API | `POST /admin-api/order/store-order/verify-pickup?code=` |
| 商家「已取餐」 | 工作台自取按钮文案；`/order/pickup-verify` 核销页 |
| 学生端取餐码展示 | 订单详情优先展示 `verifyCode` |
| 首页 IA | 店列表自取（对齐 `web/` 设计） |

## 仍弱 / 后续

| 项 | 说明 |
|------|------|
| 真扫码摄像头 | 管理端目前输码；小程序扫码可再接 `scanCode` |
| 微信支付真联调 | 需商户号 + 回调域名，见 `WECHAT_CONFIG.md` |
| 骑手 / 派单 | P1，明确不做 |

## 结论

开源自取核销原状：**商家确认（出单→收货）**，不是扫码核销。  
本仓最小补齐：**核销码 + 输码核销 API + 已取餐 UI**。
